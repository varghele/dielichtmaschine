# v1.5.5 hardening plan

Branch `v1.5.5-hardening`, cut from `v1.5-focus-morphing` at `32dbd1e`
(2026-10-06). Source: the codebase assessment of 2026-10-06 (core/output,
GUI/visualizer, tests/tooling passes). This release fixes correctness,
threading and lifetime bugs and closes infra gaps; it adds no features.

## Ground rules

- One group per commit, each with the tests that prove the fix (a test
  that fails on the old code wherever the bug is testable).
- Gate per group: full `tests/unit` (-n auto), `tests/e2e`, `tests/visual`
  (serial) with no new failures against the recorded baseline, plus the
  demo export hashes (`scripts/export_hash_check.py`, PYTHONHASHSEED=0).
- Export output MAY change where a fix requires it (decision 2026-10-06);
  every hash change is named in the CHANGELOG entry of the group that
  caused it. Unchanged hashes are the default expectation.
- NO rendered-pixel changes: goldens exist only for win32 and cannot be
  regenerated on the Linux run. Anything that would move pixels is
  deferred to the roadmap instead.
- Structural refactors are planned, not done (see "Deferred" below).

Baseline (Linux, Python 3.13, PyQt6 6.11, offscreen): unit 3178 passed,
8 skipped, 1 env-dependent failure in `test_screensaver.py` (which of
two tests fails varies run to run); e2e 46 passed + 2 strict xfails;
visual 45 passed, 44 skipped (win32-only goldens).

## Deferred to the roadmap (structural, need the desk or a screen)

Listed as open items in ROADMAP.md v1.5.5 (with the G4 leftovers).

- Split `MainWindow` (project IO, autosave, LTC/GDTF controllers) and
  replace index-based tab lookup / `self.window()` calls with an app

  `AudioWaveformWidget`, Qt timers in `timeline/` and `audio/`).

  goldens on the Windows job.

### 3. Known bugs left unfixed (need a redesign or a desk)

- [x] **GDTF auto-pull on quit**: the pull worker is not waited on in
  `closeEvent`, so quitting mid-download can destroy a running QThread.
  Needs a cancellable Share client (timeouts are 30-180 s).
  Done 2026-10-13: the pull runs on a daemon `threading.Thread` (result
  relayed to the UI by a queued signal) that `closeEvent` cancels and
  never joins; the Share client streams downloads and checks a cancel
  event between chunks; every download lands via `.part` + atomic
  rename; and the auto-pull stages and gates files in a temp dir, so
  an unchecked GDTF can never sit where the library would load it
  (`test_gdtf_share.py` TestDownload/TestAutoPull,
  `test_worker_threads.py::TestGdtfAutopullQuit`).
- [x] **Visualizer feed socket writes**: a client's own thread
  (initial config, heartbeat) and the UI thread's `send_update` /
  `update_config` can write the same socket at once; the client joins
  the set before its config is sent. Fix: per-client send lock.
  Done 2026-10-12 (`1459eab`): every write holds the client's send lock,
  the client registers under it so its config goes first, writes run
  on a snapshot outside `clients_lock`
  (`tests/unit/test_tcp_server.py::TestConcurrentWrites`).
- [x] **Drag during playback**: a block's start/end can be read halfway
  through a drag edit, giving one output frame with the wrong interval.
  Needs the UI-side snapshot redesign (G6 note).
  Done 2026-10-13, without the redesign: the tear is on the WRITER side
  (a drag shifts start, end and each sub-block in separate statements),
  so no arbiter-side copy could fix it. One reentrant
  `utils/timeline_edit_lock.TIMELINE_EDIT_LOCK` is held by
  `ShowsArtNetController.render` around scheduling + `update_dmx`, and
  by every multi-field interval write in `light_block_widget`
  (envelope drag, edge resizes, sub-block drag/resize, shift-copy
  reset) and in `MoveBlockCommand` / `ResizeBlockCommand`
  (`test_output_thread_safety.py::TestTimelineEditsDuringPlayback`).
  Dialog edits of a single block still write unlocked; each writes one
  block on accept, outside a drag.
- [x] **GL context recreation** starts the engine with no fixtures
  (pre-existing; nothing reparents a GL widget today).
  Done 2026-10-13: `RenderEngine` keeps the last fixtures, grid size,
  plane highlight and per-universe DMX it was given (never cleared) and
  `initializeGL` replays them (`_replay_state`, was the clearing
  `_flush_pending_state`), so a recreated context comes back as it
  was; covers the Stage/Shows/Auto previews and the standalone viewer.
  The orientation preview already rebuilt from Python state.
  `test_render_engine_pending.py::test_recreated_context_replays_the_last_state`.
- [x] **Orientation preview** never releases the VBOs behind its
  per-fixture-type geometry; leaks once per fixture-type change.
  Done 2026-10-12 (`99d2935`): the fixture-type builders track every
  buffer and VAO they create (including the per-type axis VAOs the old
  release list missed) and a type change releases them all, VAOs first;
  pinned with mocks and on a real standalone moderngl context
  (`tests/unit/test_gl_lifetime.py`).
- [x] **CSV rig sheet** (`utils/fixture_io.write_fixture_list_csv`)
  writes only the primary group, so a CSV round trip drops secondary
  groups (JSON keeps them). File-format decision. Decided 2026-10-12:

  xfail (`tests/unit/test_fixture_io.py::TestCsvSecondaryGroups`).

- [x] **Capabilities cache** still caches its safe default when no
